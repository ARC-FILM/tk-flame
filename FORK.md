# tk-flame — Arc Film studio fork

Studio fork of [`shotgunsoftware/tk-flame`](https://github.com/shotgunsoftware/tk-flame).
Maintained because we carry real code changes in `python/tk_flame/` (CDL-preset
patching on preview/thumbnail generation) plus a manifest change to load a new
framework. These can't live as loose patches on a host — and the CDL logic depends
on `arc_xml_patcher`, which is being lifted out into its own framework.

> **This migration = two moves at once:**
> 1. Carry the real edits from the hand-edited cache copy of **`v1.19.2`** up onto a
>    fresh fork branch based on **`v1.19.10`** (current upstream latest).
> 2. Extract `arc_xml_patcher` out of the engine's `python/` and into a new
>    framework, **`tk-framework-arc-utils`**, then wire the engine to load it.
>
> `tk-flame` is an **engine**, not an app — so its settings are configured under the
> `engines: tk-flame:` block of the Flame environment, not an app block.

Baseline for the diff below: [`tk-flame_fork.md`](./tk-flame_fork.md), generated by
`fork-compare.sh` against the cache copy at
`/Volumes/ArcFilm/_FLOW_Configs/25170_VFX_RND/install/app_store/tk-flame/v1.19.2`.

## Fork-side patches (live on `arc-main`)

These are the only things that actually justify a fork of the engine.

1. **`info.yml` — add a `frameworks:` block** declaring `tk-framework-arc-utils`
   (stock `tk-flame` declares no frameworks). Minimum version pinned; the concrete
   descriptor lives in the config's `framework_locations.yml`, not here. This manifest
   change is what lets the engine's Python reach the patcher module. Apply **before**
   patch #2 (the code won't import without it).

2. **`python/tk_flame/thumbnail_generator_flame.py`** — the CDL-preset patching.
   In both the preview path and the thumbnail path, before the `transcoder.transcode(...)`
   call, resolve a shot-specific preset and pass it as `preset_path=new_preset_path`:
   ```python
   # near the top of the module, or lazily inside the method:
   fw = self.engine.frameworks["tk-framework-arc-utils"]
   patcher = fw.import_module("arc_xml_patcher")
   ...
   # preview path (was: preset_path=self.engine.previews_preset_path)
   new_preset_path = patcher.create_proxy_template(
       self.engine.previews_preset_path, asset_info, self.engine)
   # thumbnail path (was: preset_path=self.engine.thumbnails_preset_path)
   new_preset_path = patcher.create_proxy_template(
       self.engine.thumbnails_preset_path, asset_info, self.engine)
   ```
   Replaces the old local import `from .arc_xml_patcher import create_proxy_template`.
   **⚠ VERIFY on re-apply — this patch conflicts against `v1.19.10`.** Upstream
   reformatted the exact anchor lines (see *Upstream drift* below): the tuple lost its
   parentheses, so the original context won't match. Re-anchor by hand.
   **DECIDE:** the `sg = self.engine.shotgun` line under `#get LUT from IPC if available`
   is assigned but unused in the current diff — a stray experiment. Drop it unless it's
   actually feeding the LUT lookup.

## Framework extraction — `arc_xml_patcher` → `tk-framework-arc-utils`

Spans two repos; do this **first**, because patch #2 imports from it.

- New repo `<yourorg>/tk-framework-arc-utils`, standard framework skeleton
  (`info.yml`, `python/`, `__init__.py`).
- Move **`arc_xml_patcher.py`** into the framework's `python/` as an importable module.
  Reached from consumers via `fw.import_module("arc_xml_patcher")`.
- **Do NOT** carry `arc_xml_patcher_bu_251217.py` — it's a dated backup, not source.

**The move itself is clean — nothing breaks on relocation:**
- Imports are **stdlib only** (`json`, `xml.etree`, `pathlib`, `itertools`, `re`,
  `datetime`, `os`). **No `from .xxx` intra-package imports** — it never reached back
  into `tk_flame/`, so it relocates with zero import rewrites.
- **No hardcoded studio paths in the patcher.** All colour dirs (`cdl_dir`, `xml_dir`,
  `lut_dir`, `input_transform_dir`) are derived at runtime from `asset_info["exportPath"]`
  (or `destinationPath`). The `/Volumes/7010_TENZING_VFX/...` paths were only in
  `info.yml` (patch #3), not here — so this file needs no path config.
- **Entry-point signature:** `create_proxy_template(preset_path, asset_info, engine)`
  — three args. It reads `engine.shotgun`, `engine.context.project["id"]`, and
  `engine.log_info(...)`. Plain utility function, not a hook and no framework settings
  needed — the engine handle is passed in by the caller (patch #2).
- **Drop the `if __name__ == '__main__':` block on the way in.** It's dead: it calls
  `create_proxy_template(test_preset_path, test_asset_info)` with **two** args (would
  `TypeError` today), and hardcodes `/Users/mel-film02/...` test paths. Frameworks never
  run as `__main__`; delete it or move it to a real test under `tests/`.

- Wire-up: engine `info.yml` `frameworks:` block (patch #1) + a descriptor in the
  config's `framework_locations.yml`.
- Tag/release the framework independently: `v0.1.0` (or `-arc.N` if you're basing it
  on an upstream skeleton).

### Known bugs to fix while you own this (don't carry them silently)

The author's own comment (`# This fucking sucks and I want to rebuild this`) is a fair
warning. These bite inside preview/thumbnail generation — i.e. the exact silent-failure
surface. Decide on each before the first framework tag:

- **Dead fallback branch + `None` crash (highest priority).** The LUT resolution uses
  `if shot_ipc_lut_data: … elif not lut_data: … elif not lut_data:`. Since `lut_data`
  is `None` when the first `elif` is evaluated, that branch *always* wins when there's
  no shot IPC — so the **third branch (directory-scan fallback) is unreachable**. Worse:
  when neither shot nor default IPC returns a LUT, `lut_data` stays `None`, and the later
  `if export_path and lut_data["lut_name"]:` dereferences `None` → `TypeError`, killing
  the export. Restructure as nested `if`s (shot → default → dir scan), and guard the
  `lut_data`-is-`None` case before the CTBItem loop.
- **`NameError` when `export_path` is falsy.** The `else` branch sets `cdl_dir/xml_dir/
  lut_dir = None` but never sets `input_transform_dir`; the very next line opens
  `input_transform_dir / "IPC_translation.json"`. Any missing export path → `NameError`.
- **Fallback globs the wrong dir.** `lut_list = … cdl_dir.glob("*.cube") … if lut_dir…`
  — globs `cdl_dir` but guards on `lut_dir`. Reads LUTs from the CDL directory. (Moot
  until the dead branch above is revived, but fix it then.)
- **Mac-only path key.** LUT paths read `['local_path_mac']`. If any Flame host is Linux
  (common for Flame), use `local_path` (OS-resolved) or branch per platform.
- **Tabs, not spaces.** File is tab-indented; if the framework repo runs black/pre-commit
  (upstream Toolkit does), it'll reformat on first commit — do that reformat as its own
  commit so it doesn't muddy the logic history.


   > another project's volume. Fine as a config value, but confirm every host/project
   > that loads this config can see that mount, or template it.

4. **`hooks/project_startup.py` → config-level hook override** (Bucket B, no fork).
   Chain the hook setting in the env, app/engine block:
   ```yaml
   project_startup_hook: "{self}/project_startup.py:{config}/tk-flame/project_startup.py"
   ```
   Then `config/hooks/tk-flame/project_startup.py` overrides only `get_project_settings`,
   delegating the rest to `super()` (the version-conditional proxy branches stay owned
   upstream):
   ```python
   import sgtk
   HookBaseClass = sgtk.get_hook_baseclass()

   class ProjectStartupActions(HookBaseClass):
       def get_project_settings(self):
           settings = super().get_project_settings()
           settings["FrameWidth"]  = "3840"
           settings["FrameHeight"] = "2160"
           settings["FrameDepth"]  = "16-bit fp"
           settings["StartFrame"]  = "1001"
           return settings
   ```
   > **DECIDE:** `StartFrame` is **not** in upstream's documented wiretap key set
   > (FrameWidth/Height/Depth/FieldDominance/VisualDepth/AspectRatio/FrameRate + proxy).
   > Confirm wiretap project setup actually honours it before relying on it.
